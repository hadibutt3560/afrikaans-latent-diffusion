# AR checkpoint validation audit: fixed diagnostic protocol

Frozen before fresh model inference on 22 October 2026. This is exploratory validation work after historical test exposure, not a final hypothesis test. No training, paid compute, cluster submission or historical-output replacement is authorised by this protocol.

## Question and decision

Can run `ar-baseline-57759`, selected step 60,000, supply a technically valid historical comparator? First verify export identity, tokenisation and the original validation score. Then assess unconditional sampling and whether the historical length cap affects it. A usable checkpoint avoids unnecessary retraining for a contextual comparison. A prospectively matched, replicated AR experiment remains a separate design decision.

## Fixed procedure

1. Compare the saved safetensors model, loaded strictly, with every tensor in `best.pt`; verify the stored architecture, vocabulary hash and train/validation split hashes. No test file is read. Compare the saved tokenizer's encodings of all validation passages against the frozen diffusion tokenizer. Check BOS=PAD=0, EOS=1, labels and masking.
2. Reproduce the original 128-example selection subset: shuffle validation indices with Python `random.Random(42)` and take the first 128. Evaluate token-weighted CE with BF16 autocast, batch one and eager attention. Absolute difference from recorded CE 3.6071377117359407 must be <=0.02 to proceed; this is an engineering tolerance, not statistical equivalence. Also evaluate this subset in FP32. Stop on weight/tokenizer mismatches, non-finite outputs or failed reproduction; investigate before generation.
3. Evaluate all 5,905 validation passages in FP32 with batch four and the original 128-token view plus BOS. Store per-passage NLL, scored-token count, document ID and input length. This is rescoring of the selected checkpoint, not reselection. Distinguish its own causal perplexity from external mGPT perplexity and diffusion velocity MSE.
4. Generate 256 unconditional outputs per arm, independently resetting Torch/Python RNG for seeds 30000–30255. **Primary diagnostic:** maximum 127 new tokens, giving at most 128 positions including BOS, matching diffusion's total decoder-length cap. **Historical-cap control:** maximum 64 new tokens. In both arms retain nucleus sampling top-p=0.95, top-k=0, temperature=1, one beam, no minimum length, no repetition penalty or n-gram ban, FP32, batch one and cache enabled. Only the cap changes between arms. Matching the maximum position count does not make decoding algorithms or effective text lengths equivalent. Shared seeds pair only this AR cap diagnostic; they do not pair AR and diffusion outputs semantically.
5. Score both new arms and the 100 historical saved AR outputs with cached `ai-forever/mGPT`, revision `40897bd7c8b47a76802c411108ca6220438b8b40`, FP32, context512/stride256, using the preserved benchmark `score_text` function. Check a fixed small set of stored validation scores first. A relative NLL difference >1e-4 is a compatibility failure to investigate; do not combine incompatible scores silently. Empty outputs are failures and invalidate an all-sample aggregate; conditional nonempty PPL may be separately labelled.
6. Summarise all AR outputs, every diffusion training seed's first 256 stored validation-bank outputs, and the first 256 stored real-validation references. Do not select a favourable diffusion seed. Also retain the full 1,000-output diffusion-bank summaries as context; sample-count-sensitive diversity must use the equal-size subsets. Use pooled token-weighted PPL, whitespace-word distinct-1/2/3, per-output trigram repetition, length, EOS/cap/sentinel incidence, and exact NFC/casefold/whitespace-normalised training matches.
7. Compute 2,000 fixed-seed bootstrap replicates for conditional sample PPL and the paired AR length-cap difference; use document-cluster resampling for full-validation CE. These intervals describe this fixed checkpoint/sample process, not AR training-seed uncertainty. Report all five diffusion seeds and their sample SD separately. Do not perform an architecture-superiority significance test or mark the proposal's 1.20 criterion passed.
8. Inspect a fixed random sample of 20 primary-arm outputs (selection seed 20261022), supplemented by explicitly labelled worst-score, repetitive and copied examples. This is AI-assisted diagnostic inspection, not a blinded human study or a fluency prevalence estimate. Save a blinded review sheet for future competent human review without claiming it has occurred.

## Boundaries and resource estimates

Use the existing RTX3060 12GB and cached models. Estimate 15–60 GPU minutes, with a hard one-hour budget per inference stage and progress checkpoints. Peak memory is expected to fit 12GB when AR and mGPT are loaded sequentially; this is an estimate. Stop on OOM or non-finite results rather than silently changing precision or sample counts. No training or package installation. Preserve partial diagnostics if a stage fails.
